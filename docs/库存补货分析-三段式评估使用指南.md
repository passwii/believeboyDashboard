# 库存补货分析三段式评估使用指南

> 版本：v1.2 · 2026-08-01
> 适用对象：运营、采购、SKU 管理
> 关联页面：仪表盘 > 供应链 > 库存补货分析

---

## 摘要（30 秒看懂）

- 过去：每个 SKU 只看一个数字（还能卖多少天）→ 同样剩余天数、不同趋势的 SKU 都被标成一样的状态
- 现在：每个 SKU 同时被贴上 **状态**（是什么）+ **行动**（做什么）+ **信号**（为什么）三组标签
- 特别关注新增的 **趋势转差** 状态（原本正常但在变差），以及 **季节性** 修正（旺季淡季分别处理）
- 完全向后兼容：老页面、风险状态 emoji、旧统计字段都没变

---

## 一、为什么要升级

**过去的做法**：用一个数字（还能卖多少天）来判断这个 SKU 是"健康"还是"危险"。两个 SKU 卖断货的剩余天数一样，结论就一样。

**问题**：实际上同样剩余天数、不同趋势的 SKU 处境完全不同。

- SKU A：剩余 30 天，但最近 7 天销量比过去一个月还好（卖得越来越快）→ 真正危险，需要立刻补货
- SKU B：剩余 30 天，但最近 7 天销量比过去一个月差很多（卖得越来越慢）→ 可能在滞销前自己消耗完，不一定需要补货

旧系统会把这两个 SKU 都标成"健康库存"，运营只能靠经验自己判断。

**新做法**：把"库存状态"和"应该做什么动作"分开看，再叠加"季节性"修正——让系统告诉你 SKU 真正处于什么情况、应该采取什么动作。

---

## 二、新评估体系：三个层次

升级后，每个 SKU 会被同时贴上三组标签。运营只需要看这三组就能决定下一步。

### 第 1 层 · 状态（这是什么情况）

| 状态 | 含义 | 典型情形 |
|---|---|---|
| 健康 | 库存、销量、库龄都在健康带 | 常规运转中 |
| 关注 | 边缘状态，有 1 个指标轻微偏离 | 需多看几眼 |
| 趋势转差 | 多个指标在向下走——这是新增的状态 | 原本健康但在变差 |
| 危险 | 断货风险或严重滞销 | 需立即处理 |
| 数据缺失 | 没有销量数据或快照太久 | 需补数据 |

> **重点关注**：趋势转差 —— 这是过去系统缺失的。SKU 表面还正常但已显出下滑迹象时，新系统会主动标记，给运营反应时间。

### 第 2 层 · 行动（建议做什么）

| 行动 | 含义 | 何时用 |
|---|---|---|
| 紧急补货 | 立刻下单 | 断货风险迫在眉睫 |
| 按计划补货 | 正常走流程 | 在卖、库存偏低 |
| 暂停补货 | 先别下单 | 数据不全或趋势不明 |
| 降价清货 | 主动去库存 | 即将严重滞销 |
| 创建移除订单 | 走移除流程 | 库龄超过 1 年的货 |
| 不动 | 保持现状 | 状态稳定 |

> **关键**：行动和状态不一定一一对应。同一状态、趋势不同可能推荐不同动作。

### 第 3 层 · 信号（判断依据的原始数据）

为了让运营知道系统为什么这样判定，每行 SKU 还附带完整信号数据：

- 还能卖多少天
- 近 30 / 14 / 7 / 3 天每天平均销量
- 销量趋势比值（短期比长期）
- 库龄分档比例（新鲜/老化/超过 1 年）
- 在途数量与可售比例
- 季节性相位（见第三节）
- 数据可信度（高 / 中 / 低）

运营想看明细可点开看，无需问研发要数据。

## 三、季节性：为什么有这一层

同一个剩余天数，在旺季和淡季含义完全不同。

- **旺季**（如 7 月、圣诞前）：销量是平时的 1.5 倍以上，30 天其实很紧张
- **淡季**（如 2 月）：销量不到平时一半，30 天绰绰有余
- **常态**：和去年同期差不多

### 自动判定逻辑

1. 如果这个 SKU 去年同期有销量数据 → 系统自动算出"当前销量 / 去年同期销量"的比例，判定当前是旺季、淡季还是常态
2. 如果没有去年同期数据（新店铺 / 数据历史太短）→ 系统不强行判断，季节性显示"未知"，主流程照常工作

### 季节性标签（6 档）

| 标签 | 含义（当前销量 vs 去年同期） | 何时启用 |
|---|---|---|
| 旺季 | ≥ 130% | 有去年同期数据 |
| 向旺季 | 110% – 130% | 有去年同期数据 |
| 常态 | 90% – 110% | 有去年同期数据 |
| 向淡季 | 70% – 90% | 有去年同期数据 |
| 淡季 | ≤ 70% | 有去年同期数据 |
| 未知 | 没去年数据 | 全新 SKU / 店铺太新 |

### 季节性如何影响决策

- **旺季 + 即将断货** → 升级为"紧急补货"，建议多备一些
- **淡季 + 销量在掉** → 不急于降价，可能是季节性回落，先观察
- **常态** → 常规判定

## 四、新旧对比

| 维度 | 旧系统 | 新系统 |
|---|---|---|
| 判断维度 | 单一（剩余天数） | 多维（剩余天数 + 趋势 + 库龄 + 在途 + 季节性） |
| 趋势识别 | 不识别 | 识别"上升/稳定/下降"，明确"趋势转差"独立状态 |
| 季节性 | 不考虑 | 自动基于去年同期数据判定，淡旺季分别处理 |
| 标签数量 | 1 个（状态） | 3 组（状态 + 行动 + 信号） |
| 动作建议 | 仅状态 | 6 种互斥动作，可直接落地 |
| 透明度 | 看不到依据 | 每个 SKU 附带完整信号数据 |

## 五、运营日常使用指南

### 一日工作流（建议顺序）

1. 打开补货分析页面
2. **按"行动"列排序**（从紧急开始往下看）：
   - **紧急补货** 的 SKU：今天就要下单
   - **按计划补货** 的 SKU：本周排进采购计划
   - **降价清货** 的 SKU：和营销协调折扣
   - **创建移除订单** 的 SKU：联系仓储处理长期呆滞库存
   - **暂停补货** 的 SKU：等数据更全再决定
   - **趋势转差** 但还没动：本周重点关注，下周复查
3. 抽查 **季节性** 列：旺季 SKU 是否已被识别为紧急，淡季 SKU 是否没被错误打折
4. 抽查 **数据可信度**：低可信度的 SKU 是否需要先补数据

### 季节性快速判断

| 显示 | 含义 | 建议 |
|---|---|---|
| 旺季 / 向旺季 | 需求高 | 优先备货，补货量可上调 |
| 常态 | 正常 | 按常规 |
| 淡季 / 向淡季 | 需求低 | 不盲目备货；销量下降先别急着清货 |
| 未知 | 没去年数据 | 不影响主流程，按当前判断处理 |

### 趋势列快速判断

| 显示 | 含义 | 行动 |
|---|---|---|
| 加速上升 | 7 天比 30 天好，且趋势在加强 | 备货 |
| 稳定 | 短期和长期差不多 | 常规 |
| 减速下降 | 7 天比 30 天差，但趋势可能在回稳 | 观察 |
| 加速下降 | 短期比长期差很多，且还在恶化 | 主动处理 |

### 数据可信度快速判断

| 可信度 | 含义 | 运营建议 |
|---|---|---|
| 高 | 销量齐全 + 库龄齐全 + 快照新鲜 | 可信任系统判定 |
| 中 | 缺一项 | 部分信任 |
| 低 | 缺多项或快照陈旧 | 运营判断权重应更高 |

## 七、常见问题

**Q: 旧页面打开后看起来一样？**
A: 这是正常的——风险状态列照常显示。新增的"状态 / 行动 / 季节性"在 Excel 导出里。运营日常从 Excel 看完整信息。

**Q: 为什么有些 SKU 季节性显示"未知"？**
A: 这些 SKU 没有去年同期数据（新上 SKU、店铺太新、或去年同期没销量）。系统不强行判断，主流程照常工作，运营按当前数据判断即可。

**Q: 趋势转差和危险的区别？**
A: "趋势转差"是现在还正常但已在变差；"危险"是已经出问题（断货或严重滞销）。两个都建议关注，但"趋势转差"是预警，给运营反应时间。

**Q: 旺季补货量会上调多少？**
A: 旺季+即将断货会标记为"紧急补货"（比"按计划补货"优先级更高），补货量会考虑旺季系数。具体的下单数量由采购系统根据旺季系数自动调整，运营看到的是"该补了"。

**Q: 系统的判定跟我的经验不一致，怎么办？**
A: 建议保留双方记录——运营按经验操作 + 反馈给研发。第 9 节有反馈渠道。

## 八、日常运营三原则

1. **看"行动"列，不要只看状态**——状态告诉你"是什么"，行动告诉你"做什么"
2. **重点关注"趋势转差" SKU**——这是过去系统漏掉的预警信号
3. **旺季 / 淡季要看季节性标签**——同样的剩余天数，旺季更紧急、淡季不要急着降价

## 九、反馈

新系统上线 1-2 周内，建议运营重点观察：

- 行动建议是否符合实际经验？哪些判定你想"反着来"？
- "趋势转差"标识的 SKU，后来真的恶化了吗？
- 季节性判定符合你对市场的理解吗？

反馈方式：在飞书 / 微信工作群找**研发 Damon**，附：
1. 出问题的 SKU 编号
2. 系统的判定（状态 / 行动 / 季节性）
3. 你期望的判定
4. 实际业务情况

我们会定期 review 判定规则，必要时调整。
