# 订单信息筛选区布局实施计划

> **执行说明：** 按已确认的方案在当前工作树内逐项实施，并运行页面单测与响应式检查。

**目标：** Head 只承载全局项目、站点、日期筛选；订单类型、状态、币种、订单号、SKU、ASIN 在订单信息面板中清晰分组展示。

**方案：** 移除订单页专属筛选控件对 Head 中段插槽的占用，将筛选控件放入订单信息面板标题下方。面板内用“订单属性”和“订单查找”两行组织所有页面筛选，窄屏自然换行；保留现有筛选状态、请求参数、URL 预填、懒加载选项和全局刷新行为。订单区的清空操作只重置订单专属条件，不重置 Head 中的全局项目、站点、日期。

**技术栈：** Next.js App Router、React、TypeScript、Tailwind CSS、Vitest、Testing Library。

## 全局约束

- 继续使用现有 V3 Terminal 令牌、方角、1px 边界与控件高度规范。
- 不删除、不合并、不改变任何筛选字段的查询语义。
- Head 继续使用 Terminal Header 的全局项目、站点、日期控件；当前页不向 Head 注入订单专属筛选。
- 桌面与移动端的六项订单筛选均可直接找到；窄屏通过换行适配，不引入额外折叠层。
- 遵守仓库测试分流：页面局部 UI 改动运行目标 Vitest 文件及 `pnpm lint`。

## 文件结构

- `frontend/app/dashboard/reports/order-info/page.tsx`：将页面筛选从 Header portal / 移动筛选条移入订单信息面板，并增加清晰分组和响应式布局。
- `frontend/app/dashboard/reports/order-info/page.test.tsx`：回归验证六项专属筛选均位于订单信息面板且属性筛选控件完整。
- `frontend/tests/dashboard/reports-mobile-blf616.spec.ts`：若旧 E2E 断言依赖页面筛选折叠条，更新为检查新内联筛选布局和无横向溢出。

## 实施步骤

### 任务 1：先验证筛选归属回归测试

1. 在页面测试中断言订单信息区域包含 `订单筛选` 分组、三个多选控件与订单号 / SKU / ASIN 输入框。
2. 运行该单测，确认当前实现因筛选仍在 Header 插槽而失败。

### 任务 2：移入订单信息面板

1. 删除只服务于当前页面筛选的 Header portal 与移动筛选条构造；保留 `useHeaderRefresh` 注册及刷新行为。
2. 将筛选组放在订单信息面板标题条之后、表格独立滚动区之前；属性筛选和关键词搜索分为两行，清空按钮位于属性行。
3. 窄屏使用两列属性控件与订单号跨整行的关键词网格，宽屏保持同组横向排列；保留按需加载、现有 `onChange`、debounce 与请求构造。
4. 重跑目标单测，确认六项筛选在面板内、清空仅影响订单筛选且既有搜索与全局头部同步测试通过。

### 任务 3：验证响应式与质量门

1. 更新现有移动端 Playwright 用例，使其验证内联筛选、不出现页面级横向滚动，宽表格仍在自身区域内滚动。
2. 运行订单信息页面 Vitest、该移动端 E2E 用例（若本地 E2E 环境可用）及 `pnpm lint`。
3. 对改动的 UI 文件运行 Impeccable layout detector，检查 diff 与工作树状态。

## 验收标准

- Head 不再出现订单信息页的类型、状态、币种、订单号、SKU、ASIN控件。
- 订单信息面板内可见全部六项页面筛选，且项目 / 站点 / 日期全局同步逻辑未变。
- 筛选、导出、清空、筛选选项懒加载与移动端表格内滚动既有行为通过目标测试。
- `git diff --check`、目标单测与 lint 均通过；若环境阻止某项验证，明确列出未验证项。
