# 页面头部双层筛选插槽规范

> 状态：**设计定稿（2026-10-29 修订）**
> 日期：2026-10-28
> 适用范围：`frontend/` Dashboard 页面顶部的项目级筛选插槽；以 `dashboard/operations/daily-analysis` 为示范。
> 相关文档：[顶部插槽标准化规范（BLF-997）](../../terminal-design/header-slot-spec.md)、[可展开二层页面头部设计](./2026-10-26-expandable-header-design.md)。
> 本文聚焦插槽的层级和页面接入规则；不替代现有组件尺寸、控件原子、刷新、移动端及例外规则。

## 1. 目标

建立一致的两层页面筛选头部：页面默认常驻显示两个一级插槽，依次为**项目**和**日期**；日期控件按页面的数据周期选择月份、单日或日期范围。用户点击展开箭头后，显示第二层，承载该页面其余筛选条件。

用户进入页面时即可找到项目与时间口径；低频或页面特有条件收纳在按需展开的第二层，避免所有控件挤在同一行。

## 2. 设计决策

| 项目 | 规范 |
|---|---|
| 一级插槽 | 固定两个语义位置：项目、日期；左到右排列 |
| 日期类型 | 每页选择与业务口径一致的月份、单日或日期范围控件 |
| 二级插槽 | 放置该页其余筛选条件，例如站点、SKU、状态、关键词、分类 |
| 默认状态 | 第二层收起；有二级筛选时显示可访问的展开/收起按钮 |
| 无二级筛选 | 不显示箭头，不产生空白第二层 |
| 页面切换 | 切换路由后第二层恢复收起 |
| 移动端 | 沿用页面的移动端筛选条；两层桌面插槽不改变其控件状态或筛选语义 |
| 页面操作 | 查询提交、导出、新建、上传、刷新等不因本规范自动成为筛选插槽内容，继续遵循现有操作区及全局刷新约定 |

## 3. 头部结构与交互

### 3.1 一级筛选区

一级筛选区不是一个额外的默认行，而是 Top Header 唯一 56px 主行内的固定插槽区。两个语义位置依次为项目、日期，与面包屑、页面操作和右侧全局工具同排显示。

1. **项目**：选择当前页面的数据所属项目。页面只有单项目或项目不适用时，依照页面已有业务行为处理；不得用无含义的占位控件填充。
2. **日期**：选择页面主要时间口径。允许按业务选择月份、单日或日期范围；控件标签和当前值应使周期含义清晰。

项目与日期在布局上保持左到右顺序。桌面空间不足时，只允许常驻筛选插槽内部横向滚动；不得换行生成第二条默认 Head 行，不得把项目/日期藏入次级筛选，也不得让页面操作区把它们裁切掉。

### 3.2 二级筛选行

二级筛选行默认收起，由头部的箭头按钮展开或收起。它只承载当前页面项目与日期之外的筛选条件，展开后作为 Header 的第二行出现，正文自然下移。

存在二级筛选内容时，箭头按钮应支持鼠标和键盘操作，设置 `aria-expanded`，具有明确的展开/收起可访问名称，并关联二级行。页面没有二级筛选内容时不显示按钮或空行。切换路由后收起状态重置，避免上一个页面的展开状态泄漏到下一个页面。

### 3.3 页面操作和信息内容

本规范调整的是**筛选项层级**，不要求把所有顶部元素搬进两层筛选插槽。写操作、导出、页面导航/Tab、KPI 与统计磁贴、刷新入口按既有规范留在操作行或正文；已注册全局刷新的页面不得再增加重复刷新按钮。操作即使视觉上靠近筛选，也不因此成为筛选项。

## 4. 示例：每日分析

路由：`/dashboard/operations/daily-analysis`

| 层级 | 控件 | 说明 |
|---|---|---|
| 一级，常驻 | 项目 | 选择分析数据所属项目 |
| 一级，常驻 | 日期范围 | 每日分析的时间口径；按页面已有支持的日期范围控件呈现 |
| 二级，默认收起 | 站点/国家 | 缩小分析数据的站点范围 |
| 二级，默认收起 | SKU 搜索/选择 | 缩小分析数据的商品范围 |
| 正文 | KPI、图表、表格等分析内容 | 不属于头部筛选插槽 |
| 移动端筛选条 | 项目、站点、日期、SKU | 保留移动端完整筛选入口及原状态绑定 |

桌面端初始状态仅展示项目与日期。点击箭头后，第二层展示站点与 SKU。再次点击收起第二层。调整任一筛选值仍使用页面现有状态、查询触发和数据加载规则；本规范不改变 URL、缓存或 API 参数契约。

目前代码已经提供常驻筛选和次级筛选独立挂载能力；每日分析页通过 `DailyAnalysisHeaderSlots` 把桌面控件路由到两层插槽，并将移动端控件交给现有移动筛选条。这是本规范推荐的页面接入模式。

## 5. 页面接入规则

新增页面或迁移页面时：

1. 明确页面项目选择的来源与行为，放入一级项目位置。
2. 明确页面的主时间口径与粒度，选择月份、单日或日期范围控件，放入一级日期位置。
3. 将剩余筛选条件放入二级插槽；无剩余筛选时不注册二级内容。
4. 保持筛选状态由页面原有状态源管理；桌面层级变化不复制或重建筛选状态。
5. 移动端继续提供可用的筛选入口，并复用同一组受控值和回调。
6. 按 BLF-997 继续遵循插槽控件高度、宽度、移动端可达性、筛选排序、刷新去重等规则。层级规范不豁免既有控件标准。
7. 页面操作和内容视图继续按其语义放在操作区或正文，不混入二级筛选。

## 6. 例外与边界

- **项目确实不适用**（例如单一固定范围、纯静态页或无需项目维度的工作流）：不伪造项目控件；保留日期为首个有效筛选位置，并在页面说明中记录原因。此为有依据的例外，不改变通常页面的双插槽标准。
- **日期确实不适用**：不放置空日期控件，并记录页面数据不受日期维度约束的原因。
- **页面无额外筛选**：一级项目/日期照常呈现；无箭头、无二级空行。
- **视图切换**（Tabs、列表/看板切换）、KPI、创建/编辑流程和导出不是筛选项，不因位置邻近而移入第二层。
- **提交制表单**：若查询/重算按钮是筛选查询流程的一部分，按既有页面契约评估是否与对应筛选一起呈现；包含创建、编辑或多步确认的操作仍留在正文操作区。
- **既有全局筛选试点**：遵循全局状态与页面控件去重机制。同一视口不得重复显示项目或日期；由全局组件承担的一级筛选不再由页面插槽重复注册。

## 7. 验收标准

- [ ] 桌面端默认只有一条 56px Head 主行；项目、日期按顺序固定显示在该行的常驻筛选插槽内。
- [ ] 日期控件的粒度与页面业务口径一致：月份、单日或日期范围之一。
- [ ] 其余页面筛选位于默认收起的第二层；箭头只在确有二级筛选时出现。
- [ ] 展开/收起可通过键盘操作，`aria-expanded` 状态正确，展开后正文自然下移。
- [ ] 页面切换后第二层恢复收起；无二级筛选页面没有空行。
- [ ] 移动端的筛选可达，且桌面与移动端共用同一筛选状态和回调。
- [ ] 全局筛选与页面筛选没有重复渲染；筛选、URL、缓存及数据请求行为符合页面原有契约。
- [ ] 页面操作、刷新、视图切换和 KPI 没有被误归类为筛选插槽。
- [ ] 控件尺寸和其他共性细节符合 BLF-997。

## 8. 与既有文档的关系

- 本文规定**一级/二级筛选语义与交互**，是“默认项目 + 日期，其他筛选默认折叠”的规则来源。
- [顶部插槽标准化规范（BLF-997）](../../terminal-design/header-slot-spec.md)继续规定筛选分类、排序、宽度/高度、原子控件、移动端、刷新去重及既有页面盘点；如旧的单行排序描述与本文的层级规定冲突，桌面端优先按本文分层，层内仍沿用 BLF-997 的排序规则。
- [可展开二层页面头部设计](./2026-10-26-expandable-header-design.md)与其实施计划记录现有组件架构和每日分析试点；本文将这项已实现能力归纳为后续页面遵循的产品规范，不重新设计插槽 API。

## 9. 文档自检

- 范围限定于筛选头部的层级、交互和页面接入；不提出代码改动或迁移全部页面的实施承诺。
- 项目和日期的先后顺序已明确；日期支持粒度与页面业务需求绑定。
- “项目/日期不适用”的页面有明确例外处理，避免用空控件满足形式要求。
- 页面操作、视图、KPI 与筛选插槽边界已定义；同全局筛选去重规则一致。
