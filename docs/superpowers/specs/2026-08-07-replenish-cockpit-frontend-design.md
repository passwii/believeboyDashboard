# 补货分析前端重构：三段式决策驾驶舱设计（Decision Cockpit）

> v1.0 · 2026-08-07 · BLF-491（用户拍板：前端大胆创新，不复用旧逻辑，配合三段式体系）
> 配套后端：`docs/superpowers/specs/2026-08-01-replenish-2d-assessment-design.md`（v1.2，BEL-369，已上线）
> 现状基线：`frontend/app/dashboard/supply-chain/inventory-replenishment/inventory-replenishment-client.tsx`（26 列表格）

## 0. 背景与目标

用户确认后端三段式体系（`inventory_state` 5 状态 + `replenishment_action` 6 行动 + `signals` 原始信号 + 季节性）已上线、文档齐全，要求前端**大胆创新**：

1. **不一定要复用现在的逻辑** —— 允许用全新的设计语言、全新的设计思路。
2. **配合三段式体系** —— 让「状态/行动/信号」成为页面的组织主轴，而不是表格里多塞三列。
3. **大而全** —— 把「库存（可售/在途/库龄）、库存状态（state）、库存周期（补货指令→建仓→发货→售罄）、销售 DMS（3/7/14/30 + 加权 + 趋势）」综合到一个完整的分析界面。

## 1. 现状问题（审计结论）

- 当前页面 = 26 列表格，三段式字段只是末尾三列（状态/行动/风险状态），**行动是 6 个平铺标签，没有决策优先级**。
- 顶部统计条是「SKU 总数/危险/趋势转差/库存/在途/健康/待补」7 个无关联的数字，**看不出状态分布构成与行动全景**。
- 库龄分布（`signals.aging_share`）、趋势（`trend_label / trend_momentum`）、季节性（`seasonal_phase`）、置信度/数据新鲜度（`confidence / data_freshness_days`）**完全没展示**——而它们正是三段式「信号」层的核心。
- 库存周期（补货指令/建仓/发货/售罄四个日期）在表格里是 4 个孤立日期列，**没有时间轴直觉**。

## 2. 设计概念：三段式决策驾驶舱（Decision Cockpit）

### 2.1 页面信息架构（自上而下）

```
┌──────────────────────────────────────────────────────────────┐
│ 控制台行：项目 / 国家 / 搜索 / 状态筛选 / 行动筛选 / 快照 / 刷新 / 导出 │
├──────────────────────────────────────────────────────────────┤
│ █ 指挥带（Command Strip）：状态光谱 + 行动全景 + 库存总览 + 数据健康    │
│   · 状态光谱：5 段比例条（critical/deteriorating/watch/healthy/unknown）│
│   · 行动全景：6 行动计数（紧急补货→移除，点选即筛选）              │
│   · 库存总览：可售总量 / 在途总量 / SKU 数                       │
│   · 数据健康：数据新鲜度 + 置信度构成                             │
├──────────────────────────────────────────────────────────────┤
│ Tabs：决策工作台（默认） | 表格视图 | 日历视图                     │
│ ───────────────────────────────────────────────────────────── │
│ 决策工作台 = 按 replenishment_action 分组的行动工作台：           │
│   █ 紧急补货 REPLENISH_NOW      (n)  ← 可折叠行动道（lane）      │
│   █ 按计划补货 REPLENISH_NORMAL (n)                             │
│   █ 暂停补货 HOLD               (n)                             │
│   █ 降价清货 REDUCE_PRICE       (n)                             │
│   █ 移除订单 REMOVE             (n)                             │
│   █ 不动 NO_ACTION              (n)  ← 默认折叠                  │
│   每道 = 响应式 SKU 决策卡网格（1/2/3 列）                        │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 三个设计决策

| # | 决策 | 理由 |
|---|---|---|
| C1 | **行动维度是主组织轴**（lane 分组），而非状态 | 运营是按「我要做什么」工作（补货/降价/移除），不是按「现在是什么状态」；同一状态可能推不同行动（后端决策表已解耦 state/action） |
| C2 | 状态降为**卡片级视觉 rail + 光谱总览** | 状态仍是关键判断维度，但通过左侧色轨 + 顶部光谱条表达，避免和行动标签平级抢注意力 |
| C3 | **信号层全部上卡片**（库龄条/趋势/DMS 条/季节性/置信度/新鲜度） | 三段式第三产物就是「透明度」，不展示等于没消费后端数据 |

### 2.3 SKU 决策卡（每张卡 = 一个 SKU 的三段式仪表）

```
┌[state rail: 4px 色条]────────────────────────────────┐
│ SKU-1234A · 便携榨汁杯          [危险🔴] [紧急补货]    │
│ US · ASIN:B0XXX                                        │
│ ───────────────────────────────────────────────────── │
│ 可售 1,234     在途 567     可售天数 23                │
│ 库龄  [████░░░░]  0-90:62% 91-180:21% 181+:17%        │  ← aging_share
│ DMS   3D ▍▍ 7D ▍▍▍ 14D ▍▍ 30D ▍  加权 1.8  ↙ 下降明显  │  ← 4 窗口条 + trend
│ 周期  8/10 补货 → 8/17 建仓 → 8/24 发货 → 9/5 售罄     │  ← 库存周期时间轴
│ 季节性 🔥旺季 ×1.32  置信度 high  数据 1 天前           │
│ ───────────────────────────────────────────────────── │
│ [生产交货 30] [运输 15] [系数 10%]   [保存] [查看发货]   │
└──────────────────────────────────────────────────────┘
```

- **状态 rail**：4px 左侧色条，`critical` 红 / `deteriorating` 橙 / `watch` 琥珀 / `healthy` 绿 / `unknown` 灰。
- **DMS 条**：3/7/14/30 四窗口 CSS 迷你条，宽度 = 相对最大值；颜色按趋势（`trend_ratio_7_30 < 1` 偏红、`> 1` 偏绿）。
- **周期时间轴**：补货指令 → 建仓指令 → 发货指令 → 售卖截止（含在途优先），缺失锚点用虚线占位，今天越线标红。
- **信号行**：季节性（phase + factor）、置信度（dot）、数据新鲜度（天）。
- **设置区**：与现有表格一致的可编辑三件套（生产交货/运输/加权系数）+ 保存 + 查看发货，快照模式只读。

### 2.4 指挥带（Command Strip）设计

- **状态光谱**：一条水平堆叠条，段宽 ∝ 计数，5 段各自配色；段上标数字，hover 显示名称；**点击段 = 按 state 筛选**。
- **行动全景**：6 个计数徽章（紧急补货/按计划/暂停/降价/移除/不动），按决策优先级排序；**点击 = 按 action 筛选**；带选中态。
- **库存总览**：可售总量 / 在途总量 / SKU 数（沿用 summary）。
- **数据健康**：`data_freshness_days` 最大值徽章（绿 ≤1 / 琥珀 ≤3 / 红 >3）+ 置信度分布（high/medium/low 计数）。

### 2.5 交互与过滤

- 新增**客户端侧** `inventory_state` 与 `replenishment_action` 筛选（后端只支持 `risk_status` 服务端过滤；当前数据量 ≤200 行，客户端过滤足够）。两个筛选可叠加，作用于工作台/表格/导出。
- 行动道（lane）可折叠；`NO_ACTION` 默认折叠，其余展开。
- 保持现有能力不丢：快照（创建/编辑/选中）、Excel 导出（含 状态/行动/趋势/季节性 列）、发货抽屉、日历视图、URL 参数同步（project/country）、自动选中首个项目。

## 3. 技术方案

### 3.1 文件结构

```
frontend/components/dashboard/inventory-replenishment/
├── cockpit/
│   ├── decision-cockpit.tsx        # 工作台主体：lane 分组 + 卡片网格
│   ├── cockpit-overview.tsx        # 指挥带：状态光谱 + 行动全景 + 库存总览 + 数据健康
│   └── decision-card.tsx           # 单 SKU 三段式决策卡
└── inventory-replenishment-client.tsx  # 改：接入 cockpit 为默认 tab + 状态/行动筛选
```

### 3.2 数据流

- 沿用现有 `loadAnalysis()`（page_size=200，含 `signals` 全字段）。
- 客户端派生：`filteredRows = rows.filter(state 匹配 && action 匹配)`。
- 指挥带计数：状态/行动分布**客户端从 rows 统计**（与 summary 并存展示）；库存总览用 summary。
- 编辑/保存/发货/导出：复用现有函数，不重写。

### 3.3 类型

复用客户端现有 `AnalysisRow / Summary / RowEditState` 形状；cockpit 组件定义同名 props 结构（结构类型兼容，避免大改客户端）。

## 4. 验收标准
