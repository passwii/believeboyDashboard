## 背景与目标

在 Dashboard「工具箱」新增「跨境电商合规」页面，把用户提供的 16 张课件照片整理成可浏览、可快速定位、可用于内部自查的操作台。页面以出口业务的单证链条为主线，将分散的监管模式、9810 首单材料、报关字段及企业办理事项放进一致的信息层级。

本阶段以用户素材为唯一内容来源，暂不继续 EGO 或其他外部政策搜索。页面需明确区分「素材整理」与「主管机关现行要求」，避免将课件中的流程或清单表述成适用于所有企业的法律结论。

## 已确认决策

- 路由：`/dashboard/tools/cross-border-compliance`；页面名：跨境电商合规。
- 信息主线：采购 → 销售 → 报关 → 物流 → 收汇，帮助用户从业务证据链理解合规材料之间的关系。
- 页面分区：业务链路总览、监管模式对照、企业准入办理、9810 退税准备与首单核查材料、报关字段速查。
- 首单材料清单分组：企业与场地、采购、销售与收汇、出口履约、其他核查材料。
- 页面底部/首屏醒目位置标注：内容根据用户提供的课件整理；办理条件、材料口径及政策以属地主管海关、税务机关的现行要求为准。
- 复用 Dashboard 当前 Terminal 视觉系统及 `TermPanel` 等既有面板组件；不用新增外部图片或独立设计系统。
- 不把课件照片直接铺到页面中。它们是信息来源，页面以整理后的文字、流程和表格呈现，避免课件截图缩小后不可读。

## 内容架构

### 1. 页面标题与来源提示

- 标题：「跨境电商合规」；副标题说明页面是一份出口业务资料整理与自查参考。
- 显示「根据用户提供的课件整理」来源标识。
- 提示具体办理条件、材料清单和申报口径应以主管机关现行要求为准；页面不构成法律、税务或报关意见。

### 2. 出口业务证据链

以五个连续节点呈现资料如何串联：

1. **采购**：采购合同/订单、进项发票、采购付款银行记录。
2. **销售**：出口销售合同/订单、出口发票。
3. **报关**：申报要素准确、申报主体与业务单据相互对应。
4. **物流**：出口报关单、运输单据及运费相关发票、委托报关协议与代理报关服务发票。
5. **收汇**：完整银行收汇记录，并与销售及出口业务材料对照。

桌面端使用横向流程带并可跳转至对应内容区；窄屏纵向排列或横向可滚动，但不得造成页面整体横向溢出。

### 3. 监管模式对照

提供 0110、9610、9710、9810、1039 的模式名称和课件中用于区分它们的业务场景。9810 与 0110 可作为重点比较对象，但不提供自动推荐、适用性判断或“哪个更优”的结论。该区域标注「课件场景参考」，并提示实际申报模式需结合业务事实及主管机关口径确认。

### 4. 企业准入办理

将课件展示的办理事项整理成可扫读的顺序：经营范围、海关备案、电子口岸、DXPID、外币账户、出口退（免）税备案。页面只呈现素材中的事项及其逻辑关系，不宣称所有企业均须按此固定顺序办理；实际条件和顺序因地区及企业情况可能不同。

### 5. 9810 退税准备与首单核查清单

将课件中的 9810 资质条件作为独立说明区呈现；首单材料按下列分组展示：

- **企业与场地**：首次申报核查表、出口退税汇总/明细申报表、租赁合同或产权证明、近月租赁发票、固定资产明细、办公场地照片、员工清册、近月工资银行记录、社保记录。
- **采购**：采购合同/订单、进项发票、采购付款银行记录。
- **销售与收汇**：出口销售合同/订单、出口发票、完整银行收汇记录。
- **出口履约**：出口报关单、运输单据及运费相关发票、委托报关协议与代理报关服务发票。
- **其他核查材料**：实地核查自我评估表、风险提示提醒函。

材料清单增加本地自查交互：每项可勾选，显示已核对数量/总数和完成比例，提供「重置」恢复初始状态。勾选状态只存在于当前页面会话，不上传、不写入后端、不承诺刷新后保留。区域需说明这只是课件所列材料，具体清单以属地主管部门要求为准。

若课件中的资质条件无法从原图确认具体措辞或适用边界，实现时仅逐项按可辨认原文整理，不自行补写条件；无法准确转录的内容应省略并在交付时列出，不用猜测填充。

### 6. 报关字段速查

以字段名 + 简短解释/校对提示呈现素材涉及的申报信息：境内发货人、境外收货人、生产销售单位、合同号、商品编码/名称、原产地、贸易国、运抵国、成交方式、数量与单位、币制。描述用于帮助理解字段，不生成报关值、不判断填报正确性。

## 视觉与交互

- 沿用 V3 Terminal 主题令牌、零圆角和既有面板边界规则；保持轻量、工具化的控制台观感，以清晰的信息层级而不是装饰性大图建立视觉重点。
- 标题区之后先给出五步业务链路；其后按模式、办理准备、首单清单、字段速查展开。各区使用稳定编号和页内锚点，方便长页面定位。
- 桌面端优先用分栏和信息卡片组织密集内容；移动端改为单列，模式对照和字段列表使用可读的卡片/行式布局，不压缩为不可读的小表格。
- 自查项使用原生可访问的 checkbox，支持键盘操作并有清晰的标签；进度文本随选择更新。重置需有可辨识的按钮文案，不使用图标作为唯一说明。
- 动效仅用于轻量进入/状态变化，并尊重 `prefers-reduced-motion`；页面无轮播、弹窗、文件上传或需要登录以外的新增状态。

## 实现边界

- 新增 Next.js 页面路由、页面组件与必要样式；在 `frontend/lib/sidebar-config.ts` 的「工具箱」组添加入口，并补齐路由标题/元数据所需映射（若项目现有路由元数据机制要求）。
- 页面内容是前端静态参考信息；清单交互只管理组件本地状态。
- 不新增 API、数据库、迁移、权限、持久化或外部依赖。
- 本阶段不做外部法规搜索、模式推荐问答、退税金额计算、材料上传/导出或官方政策自动更新。

## 验收标准

1. 通过「工具箱」导航可打开新页面，页面标题、路由和来源提示正确。
2. 页面完整覆盖五步出口业务链路、五种监管模式、企业办理事项、9810 首单材料和报关字段；材料分组与本设计一致。
3. 模式及首单材料均明确标注为课件整理参考，并提醒以主管机关现行要求为准；不出现未经核实的适用性结论。
4. 用户可勾选/取消首单材料，核对数量与比例即时更新；重置恢复空状态；数据不发送到后端。
5. 桌面端层级清晰；移动端无需整体横向滚动即可阅读所有内容，页内锚点可操作。
6. 明暗主题均遵循现有 Terminal 令牌，交互组件有键盘与可访问名称。
7. 单测覆盖页面内容关键区块、清单统计/重置交互与导航入口；按仓库 T 档规则运行验证。由于会改动公共侧栏配置，应通过影响分析确定验证档位，并按仓库规则完成测试与 lint。

## 风险与口径

- 课件内容可能不是最新法规或覆盖所有情形；通过来源标签、限制性提示及不做法律判断来控制误读风险。
- 原图中若存在模糊或不完整文字，不通过外部搜索或推断填补；先保留可确认信息，后续如需补充由用户提供明确材料或另行授权检索。
- 9810 首单材料属于素材列举的参考清单，不应被页面标题、进度百分比或勾选状态误解为退税资格审核或申报通过率。
