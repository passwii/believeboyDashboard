# 库存补货分析

> 文档性质：业务说明
> 版本：v1.2 · 2026-08-01
> 关联页面：仪表盘 > 供应链 > 库存补货分析

本文档客观描述库存补货分析的数据来源、处理方式、判定维度与产物输出。不涉及具体操作步骤或前后对比。

---

## 一、文档目的

库存补货分析用于回答以下业务问题：

- 哪些 SKU 当前卖得快 / 卖得慢 / 已停售
- 哪些 SKU 当前补货不足 / 库存过多 / 库龄过老
- 哪些 SKU 已经断货或将断货
- 哪些 SKU 的需求处于旺季 / 淡季
- 每个 SKU 当前应该采取什么补货或清货动作

---

## 二、数据来源

库存补货分析的数据来自三类原始输入。

### 2.1 库存快照

来自 Amazon FBA 库存报告（按月导入），每个 SKU 一行数据：

- 当前可售数量
- 库龄分档（按入库时间划分 0-90 天 / 91-180 天 / 181-270 天 / 271-365 天 / 超过 365 天）
- 推荐动作字段（来自 Amazon 原始报告）

### 2.2 销量数据

来自 Amazon 业务报告（按日导入），按 SKU 聚合多时间窗口销量：

- 近 3 天 / 7 天 / 14 天 / 30 天销量（每日平均值）
- 去年同期同窗口销量（近 3 天 / 7 天 / 14 天 / 30 天）

### 2.3 在途与补货设置

来自补货排程模块：

- 在途货件数量（按 SKU 汇总）
- 生产周期、海运周期、安全库存系数（按 SKU 配置）

---

## 三、数据处理

将上述原始数据转换为分析所需的派生指标。

### 3.1 库存量派生

将库存快照与销量结合，计算：

- **可售天数** = 可售数量 / 加权日均销量
- **加权日均销量** = 多窗口销量按权重综合（近期权重更高）

### 3.2 趋势派生

将多窗口销量进行两两比较：

- **短期趋势**：7 天销量 vs 30 天销量的比值
- **趋势加速度**：7 天销量与 14 天销量的差，反映短期趋势是否在加强或减弱

### 3.3 季节性派生

将当前销量与去年同期销量比较：

- **季节性因子** = 当前 30 天销量 / 去年同期 30 天销量（多窗口综合）
- 当因子超过阈值时判定为旺季或淡季
- 当因子在阈值附近时判定为向旺季或向淡季
- 没有去年同期数据时不进行季节性判定

### 3.4 库龄派生

将各库龄分档数量转换为占比：

- 各档位数量 / 总库存数量
- 库龄结构用于识别老化程度

### 3.5 可信度评估

根据数据完整性给出每个 SKU 的判定可信度：

- 高：销量齐全、库龄齐全、快照新鲜
- 中：缺少一项
- 低：缺少多项或快照陈旧

---

## 四、判定维度

每个 SKU 同时从五个维度评估，并结合季节性进行修正。

### 4.1 状态维度

判定 SKU 当前所处的库存状态，分为五档：

| 状态 | 含义 |
|---|---|
| 健康 | 库存、销量、库龄都在健康带 |
| 关注 | 边缘状态，有一项轻微偏离 |
| 趋势转差 | 多个指标在向下走 |
| 危险 | 断货风险或严重滞销 |
| 数据缺失 | 没有足够数据做出判定 |

### 4.2 行动维度

根据状态与趋势给出建议动作，分为六种：

| 行动 | 含义 |
|---|---|
| 紧急补货 | 立刻下单 |
| 按计划补货 | 正常走流程 |
| 暂停补货 | 先别下单 |
| 降价清货 | 主动去库存 |
| 创建移除订单 | 走移除流程 |
| 不动 | 保持现状 |

### 4.3 信号维度

将所有派生指标汇总输出，供查看明细：

- 可售天数
- 各窗口销量
- 趋势比值与加速度
- 库龄结构
- 在途与可售比例
- 季节性判定结果
- 数据可信度

---

## 五、季节性判定

### 5.1 判定逻辑

季节性基于去年同期数据自动计算，不依赖人工标注：

1. 取当前 30 天与 7 天销量
2. 取去年同期同窗口销量
3. 计算比值（多窗口综合）
4. 按阈值映射为 6 档判定

### 5.2 档位划分

| 档位 | 含义（当前销量 vs 去年同期） |
|---|---|
| 旺季 | ≥ 130% |
| 向旺季 | 110% – 130% |
| 常态 | 90% – 110% |
| 向淡季 | 70% – 90% |
| 淡季 | ≤ 70% |
| 未知 | 没有去年同期数据 |

### 5.3 判定缺省情形

当 SKU 缺少去年同期数据时：

- 季节性档位显示为"未知"
- 主流程按非季节性逻辑运行
- 不做项目级或品类级的兜底估算

### 5.4 季节性对判定的修正

季节性档位影响状态与行动的判定结果：

- 旺季 + 即将断货 → 升级为紧急补货
- 淡季 + 销量下降 → 不建议降价（可能是季节性回落）
- 常态 → 不做季节性修正

## 六、判定流程

每个 SKU 的判定按以下顺序处理：

1. **数据校验**：检查销量数据是否存在。不存在则归为"数据缺失"。
2. **季节性判定**：计算季节性因子并划分档位。无去年同期数据则档位为"未知"。
3. **可售天数修正**：根据季节性因子调整可售天数（旺季缩短、淡季延长）。
4. **状态判定**：基于调整后的可售天数、库龄、销量速度综合判定。
5. **行动判定**：基于状态、趋势、在途比例综合给出建议。
6. **信号汇总**：输出所有派生指标与判定依据。

各步骤的判定结果可能相互影响，例如：

- 状态判定会参考趋势
- 行动判定会参考季节性档位
- 信号维度独立输出，不参与判定

## 七、产物输出

每个 SKU 在补货分析页面同时展示以下信息：

| 信息 | 字段 |
|---|---|
| 基础信息 | SKU 编号、品名、ASIN、国家、项目 |
| 库存数据 | 可售数量、在途数量、库龄分档 |
| 销量数据 | 多窗口日均销量 |
| 状态判定 | 当前状态（5 档） |
| 行动判定 | 建议动作（6 档） |
| 季节性 | 当前季节档位（6 档） |
| 信号明细 | 所有派生指标的可查看明细 |

页面顶部汇总所有 SKU 的状态分布计数。

---

## 八、与其他分析模块的关系

库存补货分析与以下模块使用相同的数据源，但关注点不同：

| 模块 | 关注点 |
|---|---|
| 库存分析 | 库龄结构、推荐动作的翻译展示 |
| 库存补货分析 | 库存状态判定、补货与清货行动建议 |
| 季节性补货分析 | 多项目季节性曲线与去年同期对比 |
| 库存账本 | 月度进出流水与期末余额 |

库存补货分析复用了季节性补货分析的去年同期销量数据。
