## 页面层级与筛选

### 库存分类账

主画布保留当前操作顺序：整月 Excel 导出行、完整性/对账状态、库存 KPI、六个月趋势与分布、汇总/明细/批次三个工作 tab。汇总和明细是主工作区，批次用于上传追溯，不改成辅助抽屉。

`project_id` 与 `month` 放主筛选槽；`msku`、`fc`、`disp`、`evt` 与清除操作放次级筛选槽。移动筛选摘要显示项目、月份与已激活筛选数。保留首次挂载深链值；用户切项目或月份后按现有逻辑重置四个维度筛选。

主数据只按项目与完整自然月查询。Summary、Detail 在客户端应用维度筛选；Excel 始终导出该月全量数据，不受维度筛选影响。趋势、完整性/对账、批次各有不同筛选口径，界面不能暗示它们都受维度筛选控制。无数据月份的 `snapshot` 对象可能仍让页面显示局部空表与空工作簿；错误与真正空数据保持区分。

### 发货规划

主工作区突出所选 SKU 的 180 天 forecast、参数与预期到货计划创建/关联。SKU 清单紧邻 forecast，承担选择与比较；全项目历史发运趋势作为站点/项目级背景内容放在其后。概览指标保持紧凑，不新增汇总口径。

筛选只含项目与受支持站点 US、DE、UK；不展示日期筛选，`as_of_date` 按站点时区计算。历史范围为前 365 天到当天；forecast 从次日开始 180 天。Warm 主筛选槽承载项目/站点，移动 strip 摘要不添加日期。

增长系数、创建/编辑/取消计划批次、关联/解除关联正式货件是页面操作。取消批次保留历史，不等于删除货件；关联计划量会从预期余额扣除，避免与正式供给重复。forecast 的确定情景和计划情景继续区分正式在途/入仓、草稿货件和有效预期计划。

### 货件管理

当前 tab 的工作表格是主画布；不增加常驻只读详情 inspector。概览、费用、SKU 汇总、FBA 箱明细各自保留对应表格和统计。详情编辑留在现有表单弹窗。

项目、状态、国家与货件号多选是常驻筛选；发货日期仅在费用 tab 出现。列表固定每页 20 条，货件号选项只在首次打开时懒加载。URL 只恢复 `tab` 和 `shipment_no`，其他筛选维持页面本地状态。表格继续容器内横向滚动，不压缩/隐藏业务列。

批次 CSV 是新增批次；单批 SKU CSV 会整体替换现有 SKU 明细并清空核算成本。成本核算会写回成本/重量字段，不是纯预览；删除会连同明细永久删除，仅管理员可见且必须保留确认。FBA 模板计量单位、导出范围与标签 ZIP 跳过规则维持原样。

### SKU 信息

筛选采用提交制：项目、SKU/ASIN、站点、状态变化本身不触发查询；“查询”或编号输入回车提交。搜索至少需要项目名或 SKU/ASIN。项目名、SKU、ASIN 是包含式匹配；10 位字母数字默认按 ASIN，`SKU:` / `ASIN:` 前缀可指定。

成本、尺寸、属性、文案、标签、图片等现有工作视图按业务字段保留。表格行身份是数据库记录 ID；SKU/ASIN/FNSKU 与次级父体/品名信息按真实字段组织。数据表继续内部横向滚动；批量操作留在相应数据页签，不挤进全局导航。

桌面顶部主槽承载项目与编号搜索；站点/状态和查询/重置进入次级槽。窄屏使用可折叠筛选条，折叠摘要继续表达项目/站点/状态；展开后保留查询与重置操作。

## 不可改变的业务行为

- 保留全部现有 URL 键、请求参数、默认值、接口范围、排序/分页、刷新、tabs、导入导出、确认步骤和错误/空/加载状态；不得以统一页面模板覆盖不同页面的数据含义。
- 不更改库存分类账公式/筛选口径、发货规划 forecast 场景、货件管理成本核算副作用或 SKU 资料写入/标签规则。
- 复用已存在的 Warm controls、slots 与 MobileFilterStrip；图表、表格、sheet 与页面组合保持 page-local。第二个真实消费者证实相同交互合同之后，才考虑晋升新公共组件。
- 不改 `TerminalShell`、`--term-*`、共享 UI 默认样式、`sidebar-config.ts` 的默认配置或后端 API。此批次不加入 feature flag。

## 已发现限制与独立跟进

- 库存分类账的项目列表请求缺少页面级错误/重试；月份请求缺少竞态保护；整月明细由客户端加载且没有服务端分页。C2 页面可补齐可见的项目/月份加载错误恢复，不改业务结果。
- 发货规划候选正式货件每种状态最多检查 25 件；批次初载有短暂假空态；需复核增长系数保存后 forecast 是否重新请求。若确认请求未更新，作为本页局部行为修正并记录。
- 货件管理的 SKU CSV 替换是破坏性操作，当前没有替换前确认；详情错误可能不可见。C2 迁移要保持现有接口参数和权限，但应让操作结果可见；是否增加替换确认须作为单独 UX 决策记录。
- SKU 信息最高请求 10,000 行且没有翻页，空查询条件/失败时可能保留旧数据；输入草稿与已显示结果不完全分离。视觉迁移保持当前查询/刷新/导出语义，不静默改成另一种提交模型。
- 源码复核发现旧版 SKU 信息读写权限需要后端 owner 单独评估：项目名查询可绕过 `managed_project_ids` 过滤，按记录 ID 的写入/删除路由只有共享 API key 保护，没有显式项目范围校验。货件管理部分写路由也未见项目范围检查。C2 是前端视觉迁移，不改变这些既有权限行为；不得把 UI 隐藏控件当成后端授权修复。上线前需把该安全合同作为独立事项明确记录。
- SKU 批量标签的下载计数响应头目前不在 Next 代理允许列表；更新标签时先删旧 R2 文件、再传新文件也存在失败窗口。这些是已有接口/代理问题，C2 页面样式不应伪造更准确的成功计数或文件恢复能力。

## 视觉验证矩阵

每个页面至少检查 1440px、1024px、820px、767px、390px、320px。820px 使用紧凑 Warm topbar 和 route fallback 筛选槽；767px 与以下宽度使用 MobileFilterStrip。逐页覆盖其真实表格内部滚动、弹窗/批量动作、加载/错误/空态；长 SKU、货件号和项目名不得影响页面级宽度。
