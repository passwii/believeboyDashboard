## 二、三个方向

三个 mark 都是单色 `currentColor`、同一 `viewBox 0 0 64 64`，可互换槽位。可在 `frontend/app/dashboard/brand-draft` 里切换对比，
也可直接打开 `frontend/artifacts/blf-1553/draft/index.html`（离线单页，带真实 WebGL 动效）。

### 方向 A · Wing-cut B（推荐）

- **做法**：把三片斜切翼收敛成不对称的两道切口 —— 上切口在右上端收窄成翼尖，下切口保持整段横切。
  B 的骨架（竖笔 + 两个字碗）保持完整，切口斜边同时充当玻璃棱边的折射带。
- **为什么推荐**：它是唯一「既是新符号、又接得住已确认资产」的方向。用户已经正式确认过 B · 飞翼（BLF-1244，
  2026-10-07「已正式确认可以接入」），直接废掉会制造第二次品牌切换；演化则把已确认的语义（翼、B、钴蓝）保留下来。
- **已验证**：14 / 16 / 18 / 20 px 逐档放大 6 倍检查，两道切口在 16 px 仍是清晰负空间（见草稿页「放大 16px 检查」）。
  ≥ 24 px 时可读作 B；14 px 时下切口开始并拢，属可接受的小尺寸退化。
- **风险**：字标仍写作 `BelieveBoy`，而 mark 是单字母 B —— 现有登录页已经是这个组合，不新增不一致。
  但圆底图标（`app/icon.svg` 的 64px 圆形）与这个方形 mark 的轮廓不同，正式接入要决定 favicon 是否改方底。

### 方向 B · Ledger B

- **做法**：直边、`#101826` 的账本 B，每个字怀里横贯一条细线（或一组等距横线），把字碗读成「对账行」。
- **为什么值得讨论**：它唯一一个**把 V4 Warm Ledger 的账本隐喻写进 mark 本身**，而不是只写在 UI 上。
  对「运营中台 / 跨境电商对账」的语境最直白。
- **代价**：细线在 20 px 以下会糊成灰块（已验证）；在 16px favicon 上基本读不出结构。
  它更适合「说明性场景」（登录页、文档题图、演示封面），不适合作为 favicon / 侧栏缩略 / PWA 图标。
- **结论**：适合作为**辅助图形**（例如文档页、PPT 封面），不建议作为主标识。

### 方向 C · Wordmark b

- **做法**：小写 `b`，升部顶端斜切成翼尖，与 `elieveboy` 组成 `b + elieveboy` 的连字锁合；mark 只做识别锚点。
- **为什么值得讨论**：唯一一个**让字标承担品牌名**的方向。现有产品名 `BelieveBoy` 在中文语境里已经写作
  「彼励扶跨境」，字标锁合能同时承载英文与中文读法；而且 lowercase 锁合天然比 `B + BelieveBoy` 更紧凑。
- **代价**：单独作图标时首字母大写语义丢失（会被读成 b 而不是 B）；锁合依赖字标排版，
  在方形容器（favicon / PWA / 头像）里字标会被挤掉。需要至少 `mark + 字标` 的横向空间。
- **结论**：适合作为**横向锁合**（登录页页顶、邮件签名、页面页脚），不适合作为独立图标。

## 三、与既有资产的取舍

| 场景 | 现状 | A | B | C |
| --- | --- | --- | --- | --- |
| favicon / PWA 图标（方 / 圆） | 圆底三翼 B | ✓ 可直接方底 | ✗ 16px 糊 | ✗ 需字标 |
| Warm Ledger 侧栏 28px | 纯文字 B | ✓ | ✗ | ✗ |
| 登录页页顶 30px | 圆底三翼 B | ✓ | 勉强 | 需要横向空间 |
| 文档 / 演示封面 | 无 | ✓ | ✓ 最贴主题 | ✓ 最完整 |
| 邮件签名 | `public/logo-email.png` | ✓ 需重新导出 | ✗ | ✓ |

**推荐组合**：主标识用 A，辅助图形用 B（文档 / 封面），字标锁合用 C 的小写写法但保留 `BelieveBoy` 的首字母大写 ——
即 A + 现有字标，B 和 C 作为可选场景，而不是二选一替换。

## 四、玻璃动效的三个变体

都基于 `components/ui/liquid-glass-logo-reveal.tsx`（上游 21st.dev / zanwei `glass-icon-reveal`，MIT），
通过 `tuning` 改光学参数，没有改上游的渲染引擎。

| 变体 | 结束时 | 与上游默认的区别 | 适用 |
| --- | --- | --- | --- |
| `wing-cut` | 停在钴蓝圆角方片 + 白色 B | `keepPlate` 收束成应用图标，砍掉「玻璃松手露出裸标」那一段，总时长 2.65s | 登录页 / 品牌落地页 |
| `prism` | 停在裸标 | 放大 `dispersion` / `edgeSmear` / `cornerWidth`，让两道翼切口被折成光谱 | 展示页 / 大屏 |
| `bare` | 停在裸标 | 缩短 `glide` / `present`，玻璃只擦亮一次 | 低干扰场景 / 重复出现 |
| `upstream` | 停在裸标 | **不改任何 tuning**，用于对照 —— 跑的是 21st.dev 自己的标记，不是 Believeboy | 只作比较基准，不接入 |

三个变体都在 `prefers-reduced-motion` 下自动停在玻璃帧（上游行为，未改）。

### 为什么「变化」值得做（与上游默认的实测差异）

上游默认结尾是「玻璃松手 → 只剩裸标」。`wing-cut` 把结尾改成**收束成应用图标**：
先出现钴蓝圆角方片，再补上白色 B。差异不在配色，而在**落点**：

- 默认版结尾停在「一个裸标记」，适合展示页，但对品牌位来说没有「安装 / 落地」的语义；
- `wing-cut` 结尾停在「应用图标」，与 PWA 图标、favicon、侧栏头像同构，落点就是一个可复用的资产；
- 另外两道翼切口的斜边正好落在玻璃的棱边折射带上，`prism` 能把它们折成光谱 ——
  这是**为这个字形调的**，换成圆形或字母 O 就没有这个效果。

### 关键帧与一个实测出的参数陷阱

`frontend/artifacts/blf-1553/06-motion-keyframes.png` 用组件自带的 `time` prop 把 `wing-cut` 冻结在
`0.3 / 0.55 / 0.85 / 1.2 / 1.7 / 2.2 / 2.65s`，是**确定性可复现**的关键帧，不是靠截图时序碰运气。

看关键帧会发现一个问题：**`startZoom` 决定字形在「贴着棱边停留」那一刻还认不认得出是 B。**
逐档对拍（`2.0 / 2.4 / 3.2`）后的结论：

| `startZoom` | t≈0.35s 的画面 | 判断 |
| --- | --- | --- |
| `3.2` | 只剩上下两道横条，字怀完全出画 | 认不出 B，像加载骨架 |
| `2.4` | 能看出上下两个碗的开口 | 勉强可读 |
| `2.2` | 字形轮廓 + 两道翼切口都在画面里 | **可读，保留「大字压着棱边」的意图** |
| `2.0` | 更接近最终比例 | 停留感变弱，像单纯缩放 |

上游默认是 `2.3`（`GlassReveal21st` 把它压到 `2.3`）。本组件取 `2.2`：比默认再收一点，
让 Believeboy 的两道横向切口在停留阶段就能被认出，同时不牺牲原创作者想要的那段「大字压边」。
这属于 `tuning` 里可再调的参数，如果用户希望开头更抽象，把它调回 `2.6~3.2` 即可。
