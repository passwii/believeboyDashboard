# 发货规划

> 状态：实施中（BLF-1284）
> 关联页面：仪表盘 > 运营 > 发货规划
> 新页面：`/dashboard/operations/shipping-plan`

## 页面职责

发货规划用于查看单一项目、单一站点内未来 180 天供给约束下的 SKU 销售上限，并维护尚未落实为正式货件的预期到货计划和 SKU 增长系数。页面只保存预期计划、增长系数和计划数量与正式货件的接替关系，不复制正式货件的编号、状态、ETD、ETA 或明细。

「货件管理（Shipment Management）」继续管理正式货件，旧路由 `/dashboard/operations/shipment-management`、后端 `/api/v1/shipment-schedules` 以及 Agent `shipments` 技术域保持稳定。导航顺序为先「发货规划」，后「货件管理」。

## 预测口径

- 预测区间：站点当地日期 `as_of_date` 的次日为 `start_date`，固定 180 天，含起始日、不含 `start_date + 180 天`。
- 需求基线：复用库存补货分析 30/14/7/3 天加权得到的基础 `base_dms`，不乘安全系数。权重为 30 天 10%、14 天 30%、7 天 30%、3 天 30%；3 天窗口不可用时 7 天权重为 60%，缺失窗口按可用权重重新归一化。季节性补货的 90/30/14/7 日算法不同，不作为本页基线。
- 预测日需求 = `base_dms × SKU 增长系数`。增长系数按项目、站点、SKU 独立配置，缺省 1.0；V1 手工维护。去年同期 `orderSales` 只展示对照，不参与预测。
- 每天先将当日到货数量加入可用供给，再以 `min(预测日需求, 当日可用库存)` 计入销量。未满足需求不滚存；使用 Decimal，不逐日取整。
- 确定情景从当前可售库存开始，加入符合日期边界的在途货件与已完成货件；计划情景在确定情景上再加入草稿货件与有效、未关联计划余额。计划与确定分别从同一初始库存独立模拟。
- 前 90 天按天展示；后 90 天按自然月聚合，首尾月桶裁剪在预测范围内并返回区间起止日。

## 供给与数据质量

- 站点必须单选。全局站点为 `ALL` 时不做跨站点 SKU 汇总。
- 在途货件采用 `eta_date`，其次 `etd_date + shipping_days`，再其次 `created_date + shipping_days`；无可用日期的数量列为未知 ETA，不放入日期桶。预测开始日前已逾期的未完成货件仍可见，但不假设已到仓。
- 已完成货件只读取 `actual_inbound_date`。该日与库存快照日期都明确且实际入仓日晚于快照时，才按实际入仓日纳入供给；不晚于快照日则视为库存已含。缺日期时标记“入仓状态未核实”，不以 ETA 替代。若快照后、预测开始日前已经入仓，由于期间销量/调整未知，该 SKU 必须提示更新库存快照且不显示精确上限。
- 有效预期计划使用批次预计到仓日；开始日前的计划标记逾期，不冒充期初库存。到货日当天按可售供给处理。
- 缺少销量基线或库存快照时，精确销售上限为未知，不用 0 替代；概览分别报告有效预测 SKU 数和缺失 SKU 数，未知 SKU 不可隐式计入合计。
- 去年同期实际销量按预测日期减 365 天映射，只按已计入销售的 `orderSales`；仅成功报表完整覆盖日期时，缺订单行才表示真实 0，覆盖不足返回缺失值。
- 历史发运统计按 ETD 日期和 `in_transit` / `completed` 状态。ETD 是 V1 发运日期代理口径，不代表实际离港；缺 ETD 的货件另行计数。`include_in_history_shipping_calc` 仅用于原物流成本历史计算，不影响此处件数与数量。

## 预期计划和正式货件关联

- 预期计划按批次、预计到仓日、SKU 和数量管理，可同批包含多 SKU。
- 可将计划数量部分关联给同项目、同站点、同 SKU 的草稿或在途正式货件；正式货件进入相应供给情景后，关联数量从计划剩余量扣除，避免重复计算。
- 关联数量不得超过计划明细余额，亦不得超过该正式货件 SKU 尚未被其他计划占用的数量。已完成货件不可关联。重复提交同一计划明细与货件组合返回冲突；变更数量需先解除旧关联再重新关联。
- 编辑计划数量不得低于已关联量。替换正式货件 SKU 明细若移除已关联 SKU 或把数量降至关联量以下，后端拒绝且不做部分写入。
- 计划取消保留记录，未关联余额退出计划情景；已关联正式货件仍按自身状态进入预测。V1 不提供计划硬删除；正式货件若通过既有货件管理删除，关联随外键级联清理，有效计划余额恢复。
