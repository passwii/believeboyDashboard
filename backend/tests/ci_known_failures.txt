# CI 全量 pytest 的**既有失败**基线（对账用）。
#
# 语义：基线内的失败 = 已知问题，不阻断 CI；基线之外的新失败 = 回归，阻断。
# 维护约定：真修好了才把条目删掉；发现新失败先查根因，别直接加进来。
#
# 每行一个 pytest nodeid。
#
# ── 以下 3 条都是**环境 / 存量数据依赖**，与业务逻辑无关 ──
#
# 1) tests/services/test_project_reorder_grouping.py（2 条）
#    断言「测试库应至少有一个 is_active={True,False} 的项目」——它依赖
#    BLF_test 里从生产 pg_dump 克隆下来的存量行（7687 活跃 / 8 停用）。
#    CI 的全新空库没有这些行 → assert ids 失败。
#    修法方向：让用例自己 seed 需要的行，而不是依赖存量数据。
#
# 2) tests/services/digital/test_office_service.py::test_today_stats_only_counts_today
#    ORM 把 status 声明成 Enum(TaskStatus)（Postgres 原生 enum 类型 taskstatus），
#    但迁移建的是 varchar 列，生产库里也没有 taskstatus 这个类型 → INSERT 时
#    `p4::taskstatus` 找不到类型。生产库同样是 varchar（存量数据 0 行，
#    该 INSERT 路径没被触发过），属模型/迁移口径不一致。
#    修法方向：统一模型与迁移（要么建 enum 类型，要么 ORM 用 String + 校验）。
