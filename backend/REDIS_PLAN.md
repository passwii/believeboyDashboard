# Redis 功能规划（后续启用）

## 当前状态（2026-02-27）

- 当前后端已切换为无 Redis 运行模式：
  - API 创建任务后由进程内后台线程执行；
  - 前端继续通过 `/api/v1/jobs/{job_id}` 轮询状态，`/api/v1/jobs/{job_id}/result` 下载结果；
  - 生成日报/月报/产品分析不再依赖 Redis 可用性。

## 恢复 Redis 的触发条件

- 报表任务并发升高，明显影响 API 延迟；
- 需要优先级队列、失败重试、延迟任务、任务告警；
- 需要 API 与 Worker 独立扩缩容。

## 目标能力

- API 只负责入队，Worker 独立消费；
- 队列分级：`high/default/bulk`；
- 重试和死信机制；
- 监控：队列长度、失败率、任务耗时。

## 实施建议

1. 增加执行器开关（`inline`/`redis`）；
2. 恢复 `enqueue_job -> Redis queue` 路径；
3. 部署独立 worker 并接入监控；
4. 小流量灰度后一键切换全量。
