## 1. 执行摘要

本次审查发现**1个严重(Critical)安全问题**和**2个警告(Warning)级别问题**，需要立即修复。

系统使用 PostgreSQL 的 `bcrypt` (cost factor 12) 进行密码哈希，密码存储方式符合业界安全标准。API 有基本的管理员权限控制。但存在硬编码密码泄露和缺少强制密码修改机制等安全问题。

---

## 2. 发现的问题

### 2.1 严重问题 (CRITICAL)

#### 问题1: 硬编码默认管理员密码

| 项目 | 详情 |
|------|------|
| **文件** | `backend/scripts/seed_admin_user.py:18` |
| **文件** | `backend/scripts/init_user_accounts.py:18` |
| **严重程度** | CRITICAL (95%+) |
| **问题描述** | 管理员密码被硬编码在源代码中 |

**代码位置:**
```python
DEFAULT_ADMIN_PASSWORD = 'XeonJJ2024@'
```

**风险:**
- 如果源代码仓库公开或被泄露，攻击者可直接获取管理员账户
- 密码强度虽然符合基本要求，但不适合作为固定默认值

**建议修复:**
```python
import os

DEFAULT_ADMIN_PASSWORD = os.environ.get('DEFAULT_ADMIN_PASSWORD')
if not DEFAULT_ADMIN_PASSWORD:
    raise ValueError("环境变量 DEFAULT_ADMIN_PASSWORD 未设置")
```

### 2.2 警告问题 (WARNING)

#### 问题2: 缺少强制首次登录修改密码机制

| 项目 | 详情 |
|------|------|
| **文件** | `backend/scripts/create_user_accounts_table.py` |
| **严重程度** | WARNING (85%+) |
| **问题描述** | 用户表缺少强制修改密码的字段和逻辑 |

**当前表结构:**
```sql
create table if not exists public.user_accounts (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  email text not null,
  password_hash text not null,
  is_admin boolean not null default false,
  is_active boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

**风险:**
- 初始用户无法被强制要求更改默认密码
- 系统部署后可能存在弱密码或默认密码的账户

**建议修复:**
```sql
-- 添加字段
alter table public.user_accounts 
add column if not exists password_reset_required boolean not null default true;

-- 创建索引
create index if not exists idx_user_accounts_password_reset 
on public.user_accounts (password_reset_required);
```

同时在前端登录后检查该字段，若为 true 则强制跳转到修改密码页面。

#### 问题3: 修改密码时未验证旧密码

| 项目 | 详情 |
|------|------|
| **文件** | `frontend/app/api/admin/users/[id]/route.ts:34-36` |
| **严重程度** | WARNING (85%+) |
| **问题描述** | 管理员可以修改任意用户密码，无需验证旧密码 |

**当前代码:**
```typescript
if (password && password.length < 8) {
  return NextResponse.json({ message: '密码长度至少 8 位' }, { status: 400 })
}
```

**风险:**
- 攻击者获取管理员权限后可重置任意用户密码
- 恶意管理员可修改其他管理员密码

**建议修复:**
```typescript
// 添加 oldPassword 验证逻辑
const oldPassword = typeof body.oldPassword === 'string' ? body.oldPassword : null;

// 如果是修改自己的密码，需要验证旧密码
if (params.id === session.user.id && !oldPassword) {
  return NextResponse.json({ message: '修改密码需要提供旧密码' }, { status: 400 })
}

// 验证旧密码
if (oldPassword) {
  const verifyResult = await pool.query(
    `select id from public.user_accounts 
     where id::text = $1 and password_hash = crypt($2, password_hash)`,
    [params.id, oldPassword]
  )
  if (!verifyResult.rowCount) {
    return NextResponse.json({ message: '旧密码不正确' }, { status: 400 })
  }
}
```

### 2.3 建议性问题 (SUGGESTION)

#### 问题4: 缺少审计日志

| 项目 | 详情 |
|------|------|
| **严重程度** | SUGGESTION (75%+) |
| **问题描述** | 用户管理操作没有审计日志 |

**缺失的审计记录:**
- 用户创建/删除操作
- 用户信息修改（权限、状态等）
- 密码重置操作
- 管理员登录失败记录

**建议:** 创建审计日志表
```sql
create table if not exists public.user_audit_log (
  id uuid primary key default gen_random_uuid(),
  action text not null,
  target_user_id uuid references public.user_accounts(id),
  operator_user_id uuid references public.user_accounts(id),
  details jsonb,
  ip_address inet,
  created_at timestamptz not null default now()
);

create index idx_user_audit_log_created_at on public.user_audit_log(created_at);
create index idx_user_audit_log_target_user on public.user_audit_log(target_user_id);
```
