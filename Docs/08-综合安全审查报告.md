#### 1. API Key 暴露问题

| 项目 | 内容 |
|------|------|
| **严重程度** | P0 - 紧急 |
| **问题类型** | 认证授权 |
| **风险等级** | CRITICAL |
| **发现位置** | backend/app/core/config.py:22, frontend/.env.example |

**问题描述:**
- API Key默认值为 `change-me`，仅要求最小长度8字符
- 环境变量示例文件 `frontend/.env.example` 包含真实的Supabase URL和数据库配置信息
- 使用静态API Key进行认证，无JWT token机制，无法区分用户角色

**安全风险:**
1. 一旦API Key泄露，整个系统无权限隔离
2. 无法追踪具体是哪个用户进行了操作
3. 普通用户可访问管理员专属API
4. 生产环境可能忘记修改默认值
5. 暴露数据库连接信息和项目标识符

**修复建议:**
```python
# backend/app/core/config.py
import re
from pydantic import field_validator

def validate_api_key(cls, v):
    if v is None:
        raise ValueError("API Key must be configured")
    if len(v) < 32:
        raise ValueError("API Key must be at least 32 characters")
    if not re.match(r'^[A-Za-z0-9_-]+$', v):
        raise ValueError("API Key must contain only alphanumeric characters")
    return v

api_key: str = Field(default=None, validator=validate_api_key)
```

```env
# frontend/.env.example - 使用占位符
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_anon_key
SUPABASE_SECRET_KEY=your_service_role_key
SUPABASE_DB_HOST=db.your-project.supabase.co
```

#### 2. CORS配置过于宽松

| 项目 | 内容 |
|------|------|
| **严重程度** | P0 - 紧急 |
| **问题类型** | 网络安全 |
| **风险等级** | CRITICAL |
| **发现位置** | backend/app/main.py:11-17 |

**问题描述:**
- CORS配置 `allow_origins=['*']` 允许任何来源的跨域请求
- `allow_credentials=True` 配合 `allow_origins=['*']` 是极其危险的组合
- `allow_methods=['*']` 和 `allow_headers=['*']` 允许所有请求方法和头部

**安全风险:**
1. 攻击者可以从任意网站发起跨域请求，调用API接口
2. 违反浏览器CORS安全策略
3. 容易被CSRF攻击
4. 任何网站都可以向API发送带凭证的请求

**修复建议:**
```python
# backend/app/core/config.py
ALLOWED_ORIGINS = [
    "http://localhost:3000",
    "https://your-production-domain.com",
]

# backend/app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=ALLOWED_ORIGINS,
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE", "PATCH"],
    allow_headers=["Authorization", "Content-Type", "X-API-Key"],
)
```

#### 4. 路径遍历漏洞

| 项目 | 内容 |
|------|------|
| **严重程度** | P0 - 紧急 |
| **问题类型** | 输入验证 |
| **风险等级** | CRITICAL |
| **发现位置** | backend/app/services/job_service.py:59-63 |

**问题描述:**
- `resolve_upload_path` 函数使用用户输入的 `file_id` 直接进行路径搜索
- 未验证路径遍历字符

**安全风险:**
- 攻击者可通过 `file_id=../../../etc/passwd` 读取服务器任意文件
- 可能导致敏感文件泄露

**修复建议:**
```python
def resolve_upload_path(settings: Settings, file_id: str) -> Path:
    # 验证file_id不包含路径遍历字符
    if '..' in file_id or file_id.startswith('/') or file_id.startswith('\\'):
        raise ValueError("Invalid file_id: path traversal not allowed")
    
    # 验证file_id仅包含安全字符
    if not re.match(r'^[a-zA-Z0-9_\-\.]+$', file_id):
        raise ValueError("Invalid file_id: contains disallowed characters")
    
    candidates = list(settings.upload_root.rglob(file_id))
    if not candidates:
        raise FileNotFoundError(f"file_id not found: {file_id}")
    
    # 验证返回的路径在允许的目录内
    result_path = candidates[0]
    if not result_path.is_relative_to(settings.upload_root):
        raise ValueError("Invalid file_id: path outside allowed directory")
    
    return result_path
```

function validateRedirectUrl(url: string): string {

  try {
    const urlObj = new URL(url);
    if (!allowedDomains.includes(urlObj.hostname)) {
      return '/dashboard';
    }
  } catch {

  }
  return url;
}

3. **实现Token认证**
```python
# app/core/auth.py
from datetime import datetime, timedelta
from jose import JWTError, jwt

SECRET_KEY = os.environ.get('JWT_SECRET_KEY')  # 使用强随机密钥
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30

def create_access_token(data: dict, expires_delta: timedelta = None):
    to_encode = data.copy()
    if expires_delta:
        expire = datetime.utcnow() + expires_delta
    else:
        expire = datetime.utcnow() + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
```
