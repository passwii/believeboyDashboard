# 数据分析-销售日报 业务文档

## 1. 功能目标

将三类原始报表（销售、广告、库存）按 `SKU` 聚合并合并，生成每日销售分析 Excel 文件，供运营复盘与后续分析使用。

## 2. 业务范围

- 输入：
  - 销售报表（`txt`，制表符分隔）
  - 广告报表（`xlsx`）
  - 库存报表（`txt`，制表符分隔）
- 输出：
  - `项目名_日期_日报.xlsx`
- 处理维度：
  - 按 `SKU` 汇总
  - 输出字段固定

## 3. 业务流程

1. 选择项目名称和报表日期。
2. 上传三类报表（支持分步上传，或在提交时一次性上传）。
3. 系统校验参数和文件格式。
4. 读取三份文件并做清洗、聚合。
5. 以 `SKU` 外连接合并三份数据。
6. 写入日报模板，生成 Excel。
7. 返回下载文件。

## 4. 输入规则

### 4.1 必填参数

- `project_name`（项目名）
- `report_date`（报表日期）
- 三份文件（销售、广告、库存报告）

### 4.1.1 项目名数据源

- 项目名来源于维护文件：`backend/model_file/projects.csv`
- CSV 当前表头：`项目名称`
- 前端应优先使用“项目名下拉选择”，避免手填错误
- 若数据源异常，可临时允许手动输入（兜底）

### 4.2 文件类型校验

- 允许后缀：`txt`、`xlsx`
- 文件业务类型：
  - `sales_report`
  - `ad_report`
  - `inventory_report`

### 4.3 文件存储规则

- 上传落盘目录：`project/{project_name}/uploaded_files`
- 处理归档目录：`project/{project_name}/tmp`
- 最终产物目录：`project/{project_name}/日报`

## 5. 数据处理规则（核心）

### 5.1 销售报表处理

- 来源字段：`sku`, `quantity`, `item-price`, `order-status`
- 订单状态仅保留：`Pending`, `Shipped`, `Unshipped`
- 按 `sku` 聚合：
  - `quantity` 求和 -> `订单量`
  - `item-price` 求和 -> `销售额`
- 字段重命名：`sku` -> `SKU`

### 5.2 广告报表处理

- 保留字段：`广告SKU`, `广告ASIN`, `展示量`, `点击量`, `花费`, `7天总销售量(#)`
- 字段映射：
  - `广告SKU` -> `SKU`
  - `广告ASIN` -> `ASIN`
  - `展示量` -> `曝光量`
  - `花费` -> `广告花费`
  - `7天总销售量(#)` -> `广告订单`
- 按 `SKU` 聚合：
  - `曝光量`、`点击量`、`广告花费`、`广告订单`：求和
  - `ASIN`：取首个
- 计算字段：`单次点击花费 = 广告花费 / 点击量`（脚本当前逻辑见“待确认项”）

### 5.3 库存报告处理

- 保留字段：`sku`, `available`
- 字段映射：
  - `sku` -> `SKU`
  - `available` -> `可售库存`

### 5.4 合并与标准化

- 合并方式：按 `SKU` 做两次 `outer join`（销售 + 广告 + 库存）
- 缺失值填充：`0`
- 排序：按 `SKU` 升序
- 追加固定字段：`日期(US)`（整列填 `report_date`）
- 类型处理：
  - `订单量`, `曝光量`, `点击量`, `广告订单`, `可售库存` -> 整数
  - `单次点击花费`, `广告花费` -> 保留两位小数

## 6. 输出规则

### 6.1 输出字段顺序

1. `日期(US)`
2. `SKU`
3. `ASIN`
4. `订单量`
5. `销售额`
6. `曝光量`
7. `点击量`
8. `单次点击花费`
9. `广告花费`
10. `广告订单`
11. `可售库存`

### 6.2 文件命名

- 最终文件：`{project_name}_{report_date}_日报.xlsx`

### 6.3 下载响应

- 响应类型：`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- 下载头：`Content-Disposition` 使用 UTF-8 文件名编码（兼容中文）

## 7. 异常与提示

- 未上传文件：返回错误
- 项目名为空：返回错误
- 文件类型无效：返回错误
- 文件不存在：提示重新上传
- 处理异常：返回失败并记录日志

## 8. 日志要求

关键动作均记录操作日志：

- 上传日报文件（成功/失败/异常）
- 生成日报（成功/失败）

## 9. 待确认业务点（必须确认后再开发）

1. `销售额`是否应做货币格式与汇率转换（当前仅做数值求和）。
2. `单次点击花费`当前写法是“总广告花费 / 点击量整列”，不是逐SKU计算，需确认是否符合预期。
3. `广告订单`字段来自 `7天总销售量(#)`，是否确认为“归因7天订单”并直接作为日报当日值。
4. `report_date`格式是否固定 `YYYY-MM-DD`，是否允许补历史日期。
5. 是否要求同一 `SKU` 对应多 `ASIN` 时的处理策略（当前取首个）。
