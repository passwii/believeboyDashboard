# 数据分析-销售日报 前端需求

## 1. 页面目标

提供“上传原始报表 -> 生成日报 -> 下载结果”的完整前端工作流，确保用户可视化完成日报生产。

## 2. 路由与导航

- 建议页面路由：`/dashboard/data-analysis/daily-report`
- 侧边栏菜单：`数据分析 > 销售日报` 指向该路由
- 顶部面包屑标题：进入该页面后显示 `销售日报`（替换默认 `Dashboard`）

## 3. 页面结构

1. 顶部双卡并排区（桌面端）
- 左卡：基础参数
- 项目名称（下拉选择，支持搜索；异常时可切换手动输入）
- 报表日期（日期选择器）
- 快捷按钮：`昨天`（一键填充昨天日期）
- 右卡：生成与结果
- 执行状态（项目名称、报表日期、上传进度）
- `生成日报` 主操作按钮
- 生成结果文件名展示（成功后）
- 成功/失败/处理中状态提示
- 移动端降级：两卡上下纵向排列

2. 文件识别与上传合并区
- 智能识别拖拽框（支持多文件批量识别）
- 拖拽框下方 3 个状态栏：
- 销售报表状态
- 广告报表状态
- 库存报表状态
- 每个状态栏展示：当前状态文案 + 进度条 + 当前文件名（已选或已上传）
- 识别日志区（滚动展示识别结果）

3. 手动上传紧凑区（3行）
- 每行对应一种报表类型（销售/广告/库存）
- 行内元素：类型说明 + 文件选择 + 状态徽标 + 上传/重置按钮
- 压缩高度，避免大面积卡片造成页面冗余

## 4. 字段定义

### 4.1 表单字段

- `project_name: string`（必填）
- `report_date: string`（必填，建议格式 `YYYY-MM-DD`）

项目名选项数据源：

- 来源：`projects.csv`（由后端读取并对前端提供接口）
- CSV字段：`项目名称`
- 前端展示：`label/value` 均使用项目名称

### 4.2 上传字段

单文件上传接口参数：

- `file`（文件实体）
- `project_name`（必填）
- `file_type`（枚举：`sales_report | ad_report | inventory_report`）

上传成功返回（用于后续生成）：

- `file_path`
- `filename`
- `original_filename`

### 4.3 生成接口参数

- `project_name`
- `report_date`
- `sales_report_path`
- `ad_report_path`
- `inventory_report_path`

## 5. 前端交互规则

1. 未填写 `project_name` 时禁用上传按钮。
2. 三份文件均上传成功前，禁用“生成日报”按钮。
3. 上传中显示进度状态（至少有 loading + 成功 + 失败）。
4. 上传失败允许单独重试，不影响其他文件。
5. 生成成功后触发文件下载，并保留本次上传记录。
6. 点击“重新上传”会清理对应 `file_path`，要求重新上传后方可生成。
7. 点击 `昨天` 按钮后，`report_date` 自动填充为昨天日期（格式 `YYYY-MM-DD`），用户仍可手动修改。

## 6. 校验与错误文案

### 6.1 前端校验

- `project_name` 不能为空
- `report_date` 不能为空
- 销售/库存报告 仅允许 `.txt`
- 广告仅允许 `.xlsx`

### 6.2 错误提示建议

- 项目名称不能为空
- 报表日期不能为空
- 文件格式不支持，请上传正确格式
- 文件上传失败，请重试
- 生成失败：{后端错误信息}

## 7. 状态管理建议

可采用页面级状态：

- `formState`: 项目名、日期
- `uploadState`: 三类文件上传状态与返回路径
- `submitState`: 生成中/成功/失败
- `resultState`: 下载文件名、错误信息

## 8. API 契约（按现有脚本）

0. `GET /api/projects`
- 返回项目名列表（来源于 `projects.csv`）
- 响应示例：`[{ "name": "铨富" }, { "name": "宝勒1店" }]`

1. `POST /upload-file`
- Content-Type: `multipart/form-data`
- 用于单文件预上传

2. `POST /daily-report`
- Content-Type: `multipart/form-data`
- 提交参数并返回 Excel 二进制流

## 9. 验收标准（V1）

1. 页面顶部以“基础参数 + 生成与结果”并排显示（移动端纵向降级）。
2. 用户可分别上传三类报表，并看到独立成功状态。
3. 用户打开页面后可自动加载项目名列表，并可从下拉选择项目名。
4. 文件识别区与上传区合并，且识别区下方可见三条状态栏。
5. 用户在参数完整且三文件齐备时可生成日报。
6. 生成成功后可下载 `xlsx` 文件，文件名包含项目名与日期。
7. 任一接口报错时页面可给出明确错误提示，不出现无响应状态。
8. 刷新页面后不保留本地上传状态（V1 可接受）。

## 10. 已确认规则

1. V1 不做“预览汇总表格”再下载。
2. V1 不做“批量历史日期补报”。
3. V1 不展示后端日志ID或流水号。
4. 上传区支持“批量拖拽识别”，识别规则见《数据分析-文件识别规范》。

## 11. 设计基线（供其他数据分析页面复用）

1. 优先使用“顶部关键动作区 + 下方主工作区”的结构，避免连续堆叠多个大卡片。
2. 参数与最终动作（生成/导出）优先放在首屏，减少滚动往返。
3. 多文件流程优先合并视图：识别、状态、手动修正放在同一块，降低认知切换。
4. 对重复模块采用“紧凑行式布局”替代“大卡片复制”，优先压缩高度与信息噪音。
5. 状态可视化统一为：文案 + 颜色 + 进度条（或徽标），避免只靠颜色区分。
